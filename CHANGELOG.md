## [Unreleased]

## [3.8.1] - 2026-11-10

### Добавлено

- **Уведомление о новом уровне за голос:** XP за голос начисляется в фоне, поэтому
  повышение уровня происходило молча. Теперь минутный тикер сообщает о новых
  уровнях в канал из `/leveling channel` (если канал не задан — уведомление не
  отправляется), используя тот же шаблон `levelup_message`, что и сообщения.

### Изменено

- **Шаблонные карточки сообщества вынесены в `lib/communityMessages.ts`:** вход,
  выход и повышение уровня отправляются одним кодом из событий и голосового
  тикера, дублирование отправки убрано.

## [3.8.0] - 2026-11-10

### Добавлено

- **XP за каждое сообщение:** начисление больше не привязано к случайным 15–25 XP
  раз в минуту. Ставка задаётся в `/leveling rates message_xp:` (по умолчанию
  5 XP), антиспам-пауза — `message_cooldown:` (по умолчанию `0` — за каждое
  сообщение). Счётчик сообщений растёт всегда, даже когда очки блокирует пауза.
- **Учёт времени в голосе:** бот открывает сессию при входе в голосовой канал и
  закрывает при выходе, переходе или уходе с сервера, а раз в минуту сбрасывает
  накопленные секунды. За каждые 5 минут в голосе начисляется XP
  (`/leveling rates voice_xp:`, по умолчанию 10). AFK-канал не учитывается,
  зависшие после рестарта сессии закрываются без начисления простоя.
- **Команды по активности:** `/top metric:xp|messages|voice` — топы по очкам,
  сообщениям и времени в голосе; `/rank` показывает сообщения, время в голосе и
  место в топе; `/leveling rates` настраивает ставки, `voice_tracking:` включает
  или выключает учёт голоса.
- **Панель:** на обзоре появился виджет «Активность» — сумма сообщений, часов в
  голосе и XP, переключаемые топы и список «сейчас в голосе». Профиль участника
  показывает уровень, сообщения, время в голосе и места в топах, а настройки
  сообщества — ставки XP и переключатель учёта голоса.
- **API `GET /api/guilds/:id/activity`** для виджета активности.

### Изменено

- **Миграция схемы 9:** `levels` получила `messages`, `voice_seconds` и
  `last_message_at`, `community_settings` — ставки XP, а новая таблица
  `voice_sessions` хранит открытые и закрытые голосовые сессии.

## [3.7.1] - 2026-11-10

### Исправлено

- **Порог покрытия функций снижен до фактического минимума платформ:** на Linux
  (CI) `--experimental-test-coverage` считает 74.91 % функций против 75.55 % на
  Windows, из-за чего `npm run ci` падал на ровном месте. Порог 74 — ratchet по
  минимуму из Windows и Linux, а не по локальному прогону.
- **CI печатает `data/verify.log` при падении проверок:** раньше в логе job была
  только строка `Тесты бота · ошибка → data/verify.log`, а сам вывод тестов и
  покрытия оставался внутри раннера. Теперь шаг `Show verification log`
  (`if: failure()`) показывает причину прямо в Actions.

## [3.7.0] - 2026-11-10

### Изменено

- **Консоль бота в стиле лаунчера:** `npm run dev` и `npm start` больше не рисуют
  ASCII-баннер «PROBOT» и эмодзи. Старт показывает карточку `◈ NEXUS / runtime`
  с версией, режимом (DEV или PRODUCTION), Node, платформой и PID, этапы
  `01 CONFIG → 05 PANEL` с фазой и длительностью, а отчёт проверок — бейджи
  `CORE / CONFIG / DATA / PANEL / COMMANDS / NET / SERVER` и итог `✔ · ℹ · ⚠ · ✖`.
  Палитра и сетка колонок совпадают с `scripts/launch.ps1`.
- **Лаунчер разбирает новый вывод:** `scripts/launch.ps1` понимает маркеры
  `✔ / ℹ / ⚠ / ✖`, колонки этапов и бейджи групп, поэтому RUNTIME REPORT в HUD
  собирается как раньше, а баннер и подзаголовок бота в HUD не попадают.

## [3.6.1] - 2026-11-10

### Исправлено

## [3.6.0] - 2026-11-10

### Добавлено

- **Кэш регистрации слэш-команд:** `npm run deploy` (`scripts/deploy.mjs`) считает
  хеш тела регистрации — содержимое `src/commands/**` и `src/core/loader.ts` плюс
  `DISCORD_CLIENT_ID` и область (`guild:<id>` или `global`). Если ничего не
  менялось, запрос в Discord пропускается, маркер живёт в `data/deploy-state.json`.
  Принудительно — `npm run deploy -- --force` или `DEPLOY_FORCE=1`.
- **Кроссплатформенный запуск:** `npm run launch` идёт через `scripts/launch.mjs`.
  На Windows он делегирует `scripts/launch.ps1` (HUD не изменился), на macOS и
  Linux выполняет тот же порядок шагов без оформления — `launch:dev`,
  `launch:check` и `launch:live` поддерживаются на обеих платформах.

### Изменено

- **Пороги покрытия подтянуты к фактическим значениям** и работают как ratchet:
  бот — 57 / 78 / 74 % (строки / ветки / функции, было 57 / 77 / 73), панель —
  84 / 81 / 77 / 81.5 % (строки / операторы / ветки / функции, было
  80 / 80 / 70 / 80). Правило зафиксировано в `AGENTS.md` и `CONTRIBUTING.md`.

## [3.5.0] - 2026-11-10

### Изменено

- **Проверки идут параллельно:** `npm run verify` (`scripts/verify.mjs`) запускает
  типы бота и тестов, типы панели, ESLint, Prettier и тесты бота/панели
  одновременно. Прогон занимает ~9–11 с вместо ~45 с; шаги независимы, их вывод
  пишется в `data/verify.log` секциями, формат `data/verify-result.json` сохранён
  (добавлены `mode` и `timedOut` в шагах).
- **Лаунчер:** четыре последовательных шага `TYPES`, `LINT`, `FORMAT`, `TESTS`
  заменены одной фазой `CHECKS`; линейка стала `STOP → CHECKS → BUILD → DEPLOY`,
  `npm run launch` укладывается примерно в 25–30 с вместо ~85 с.
- **`npm run ci` = `npm run verify && npm run build`:** список шагов больше не
  дублируется в `package.json` и `scripts/verify.mjs`.
- **Кэш сборки панели:** `scripts/build-panel.mjs` сравнивает sha256 содержимого
  `web/` с маркером `web/dist/.panel-hash` и пропускает `vite build`, если
  исходники не менялись (~11 с экономии на каждом запуске бота).
  Принудительно — `npm run build:panel -- --force` или `PANEL_FORCE=1`.
- **`typecheck` в один проход:** `tsconfig.tests.json` уже включает `src/`,
  поэтому `tsc --noEmit` перед ним был лишним (~14 с в каждом прогоне).
- **pre-commit hook:** `npm run verify:fast` вместо трёх отдельных npm-команд.
- **GitHub Actions:** `push` проверяется только для `main` и тегов `v*`, остальные
  ветки — через pull request, поэтому один пуш в PR-ветку больше не запускает два
  прогона подряд.

### Добавлено

- `npm run verify:fast` — проверки без порогов покрытия для лаунчера и hook.

### Исправлено

- `npm run verify` больше не обрывается на первом падении: параллельные шаги
  доигрываются, в итоге перечислены все упавшие проверки.

## [3.4.1] - 2026-11-10

### Изменено

- **Лаунчер — единый flight deck:** вместо ASCII-арта и двойных карточек —
  компактный заголовок, фазовая линейка `STOP → … → DEPLOY`, нумерованные
  результаты шагов с длительностью и секции `── RUNTIME ──`. Режимы
  `--skip-deploy`, `launch:dev` и `launch:live` показывают только свои фазы.
- **Стартовый отчёт бота:** лаунчер разбирает вывод `startup.ts` и печатает
  компактный `RUNTIME REPORT` по группам CORE / CONFIG / DATA / PANEL /
  COMMANDS / NET / SERVER с итогом `ok · info · warn · errors` и вердиктом
  `READY` / `READY WITH WARNINGS` / `ACTION REQUIRED`. Полный чеклист и
  `BOT ›`-префиксы больше не дублируются в консоли запуска.
- **Живой HUD:** время работы, память и PID настоящего процесса бота (владелец
  `WEB_PORT` или дочерний `node`), количество строк и подсказка остановки.
- **`launch:live`:** явные секции `PRE-BUILD`, `RUNTIME` и `VERIFY`; прогресс
  показывает фазы `BUILD`/`VERIFY`, а не одну букву.
- **Строки логов бота:** `HH:MM:SS  ✔  CATEGORY  текст` — с глифом статуса,
  цветом категории и обрезкой по ширине терминала.

### Исправлено

- Последняя фаза preflight больше не остаётся «текущей» после успешного
  завершения пайплайна — линейка показывает все шаги выполненными.
- `checks-only` и `launch:live` корректно убирают нижнюю UI-панель перед
  выходом, не оставляя спиннер в приглашении командной строки.

## [3.4.0] - 2026-11-10

### Добавлено

- **`npm run launch:live`:** сначала поднимает бота и панель в отдельном окне
  `NEXUS-LIVE`, затем в текущем окне прогоняет `npm run verify` (typecheck бота
  и панели, ESLint, Prettier, тесты с покрытием) и показывает Windows-уведомление
  при ошибке. Бот остаётся запущенным; результат пишется в
  `data/verify-result.json`, полный вывод — в `data/verify.log`.
- **`npm run verify`:** фоновый набор проверок без сборки, чтобы не удалять
  `dist` у работающей панели.

### Изменено

- **Лаунчер:** новый визуальный слой — компактная карточка `NEXUS` с версией
  и режимом, единая палитра, переработанные строка шага, прогресс и итоговые
  карточки. `launch:live` показывает отдельный экран `CHECKS PASSED · BOT LIVE`.
  Логика пайплайна, проверки и запуск не менялись.

### Исправлено

- **`scripts/stop-bot.mjs`:** находит бота, запущенного через `npm run start`
  (относительный путь `node dist/index.js`), по владельцу `WEB_PORT`. Раньше
  такой процесс не останавливался, и новый экземпляр падал из-за занятого порта.
- **`launch:live` ждёт именно новый процесс:** health-check сверяет PID
  владельца порта, поэтому ответ старого экземпляра не считается успешным
  запуском.

## [3.0.0] - 2026-11-10

### Добавлено

- **CI на GitHub Actions** (`.github/workflows/ci.yml`): на каждый push и PR
  ставятся зависимости бота и панели, затем выполняется `npm run ci`
  (typecheck, lint, format, тесты бота и панели, сборка). Тег `v*` проверяется
  тем же прогоном.
- **Dependabot** (`.github/dependabot.yml`): еженедельные PR для корневых
  зависимостей, панели и GitHub Actions.
- **Тесты веб-панели:** Vitest + Testing Library + jsdom, 39 тестов —
  форматирование/склонения, палитра кейсов, парсер длительностей, заметки
  релиза и пагинация (включая регресс 2.2.1). Запуск: `npm run test:panel`.
- **CONTRIBUTING.md:** локальная настройка, обязательные проверки и релизный
  процесс.

### Изменено

- **Семантическое версионирование:** `2.2.2.2` → `3.0.0` в `package.json`,
  `package-lock.json`, `web/package.json` и `web/src/lib/constants.ts`.
- **Строгие статические проверки:** `typecheck` дополнительно проверяет
  `tests/` (`tsconfig.tests.json`); ESLint покрывает `tests/`, `scripts/` и
  `web/src` (включая `react-hooks`); Prettier форматирует панель.
- **Сборка панели обязательна:** `scripts/build-panel.mjs` падает без
  `web/node_modules` и без `web/`, а `scripts/copy-assets.mjs` — без
  `web/dist/index.html`. Зелёная сборка больше не может отдать старую панель.
- **`npm run ci`** включает `test:panel` и строгую сборку панели.
- **`uncaughtException`:** вместо логирования выполняется graceful shutdown
  с кодом 1 — systemd/Docker перезапускают бота в чистом состоянии.
- **Разбиение mega-файлов:** билдеры модалок меню вынесены из
  `features/menu/handler.ts` в `features/menu/modals.ts`, а презентационные
  части настроек — в `components/settings/moderationParts.tsx`.

- **Демо-настройки панели:** dev-режим открывает все вкладки с реалистичными

neutral/premium`, общий билдер карточек, публичные ответы с кейсами, DM-карточки,

  `npm run build` сам собирает панель, CSP разрешает встроенные `data:`-шрифты.

  кнопками Discord и в веб-панели.
- **Апелляции на любое наказание:** `/appeal submit` показывает список активных
  и недавних наказаний (бан, мут, таймаут, варн, временная роль, кик/софтбан),
  апелляция привязывается к конкретному кейсу. При одобрении снимается именно
  это наказание; добавлена миграция `case_id` и отображение кейса в веб-панели.
- **Логи банов:** причина показывает тег модератора вместо сырого ID, а в карточке
  бана/разбана появилось явное поле «Кем».
- **Кейсы в панели:** клик по последнему кейсу на дашборде открывает карточку;
  прямо из неё доступны бан/разбан, мут/снятие, таймаут/снятие, кик, варн,
  роль и заметка — с учётом прав и состояния участника.
- В профиле участника веб-панели появились мут и снятие мута, управление ролями
  (выдать/снять) и снятие всех предупреждений одним действием.
- Право `manageRoles` учитывается при доступе к панели и показывается в API.
- **Проверки при старте**: Node.js, интенты, конфигурация, целостность SQLite
  (`PRAGMA quick_check`), запись в каталог данных, свежесть бэкапов, веб-панель
  (включая `GET /health`), регистрация слэш-команд и на каждом сервере — права
  бота, иерархия ролей, Audit Log, канал логов и роль мута. `STARTUP_CHECKS=false`
  отключает отчёт, `STARTUP_STRICT=true` завершает процесс при ошибках.
  `/diagnose` использует тот же список прав.
- **Консоль**: анимированный старт — баннер с версией, спиннеры этапов
  (Discord, БД, панель), пошаговый вывод проверок и финальный блок «бот готов».
  Анимация отключается вне TTY, в CI и при `UI_ANIMATION=false`.
- **Tailscale**: `npm run tunnel` показывает постоянный адрес узла и текущее
  правило `serve`; `--apply` поднимает tailnet-only, `--funnel` — публичный
  доступ. Стартовая проверка сверяет `WEB_PUBLIC_URL`, порт и режим Funnel.
- **Запуск поверх старого**: `predev`/`prestart` вызывают `scripts/stop-bot.mjs` —
  предыдущий экземпляр этого проекта останавливается автоматически, занятый
  посторонним процессом порт показывается с PID.
- **Сессии панели в SQLite** (миграция `web_sessions`): вход через Discord
  переживает перезапуск бота и действует `WEB_SESSION_HOURS` часов.
- **Сброс наказаний при выходе участника:** варны очищаются, активные мут,
  таймаут и временная роль закрываются; активный бан сохраняется, пока он
  действует в Discord. Роли наказаний больше не восстанавливаются rolepersist.
- **Расширенная настройка автомода:** действие при нарушении (удаление, варн,
  таймаут, мут, кик, бан), длительность, удаление сообщения, пороги CAPS и
  спама, лимит упоминаний, исключения по каналам и ролям. Настройки доступны
  в веб-панели и через `/automod action`.
- **Список участников в панели:** постраничная загрузка без обязательного
  поиска, поиск по имени/нику/ID по кэшу с fallback на gateway и индикация
  неполного списка.
- **Причины в логах ролей:** для изменений ролей читается аудит-запись
  `MemberRoleUpdate` (раньше ошибочно только `MemberUpdate`), поэтому причина
  из панели/команд больше не теряется. Если причина не указана, лог пишет
  «Не указана» явно.
- **Единая команда `/role`:** `add`, `remove`, `clear` (снять все роли),
  `set` (заменить все одной), `temp` и `list`. Отдельные команды `/addrole`,
  `/removerole` и `/setrole` удалены; опасные `clear`/`set` требуют подтверждения.
  В `/menu` добавлена кнопка «Снять все», а «Setrole» переименован в «Заменить все».
- **Причины всегда в логах:** карточки действий больше не скрывают поле причины;
  если аудит Discord её не вернул, пишется «Не указана». `/clearwarns` получил
  параметр `reason`.
- **Уведомления в ЛС:** причина теперь отправляется получателю при выдаче/снятии
  ролей, временной роли, изменении ника, голосовых действиях, снятии варнов
  и решении по апелляции.

- **Переработанное меню `/menu`**: 41 действие в 6 разделах — модерация, роли,
  каналы, голос, кейсы, настройки и информация.
- `src/lib/ids.ts` — криптографически случайные короткие ID для варнов, заметок,
  правил автонаказаний и подтверждений.
- Обработчики `error`, `warn`, `shardDisconnect` и `shardReconnecting` Discord-клиента:
  сбои шарда больше не оставляют бота «онлайн», но не отвечающим.
- `countCasesByType` — агрегация статистики кейсов в SQL вместо загрузки всех кейсов.
- `fitFields` — подгонка списка полей под лимит текста Components V2.
- `scripts/copy-assets.mjs`: сборка копирует статику SPA в `dist/web/public`.
- Тесты: регрессии (вложенные транзакции, экранирование LIKE, SQL-статистика,
  пороги автонаказаний, флуд, rolepersist) и HTTP-слой панели. Всего 65 тестов.

### Изменено

- Детектор флуда учитывает и общий поток сообщений, и повторы одного текста;
  раньше ловились только полностью идентичные сообщения.
- Автонаказание выбирается по наибольшему достигнутому порогу: при правилах «3» и
  «5» четвёртый варн срабатывает по «3», пятый — по «5».
- `rolepersist` не запоминает роли участников, удалённых киком или баном.
- `/modstats` считает статистику в SQL и корректно экспортирует её в CSV.
- README: разделы про меню и веб-панель, предупреждение о `.env` и `data/`,
  обновлённая структура проекта.

### Безопасность

- Панель отдаёт CSP, `X-Frame-Options: DENY`, `nosniff` и `Referrer-Policy`.
- Куки `HttpOnly` + `SameSite=Lax`, флаг `Secure` включается для https.
- Лимит тела запроса 512 КБ, статика только по allowlist, сессии в памяти с TTL.
- При `WEB_ENABLED=true` старт блокируется без `DISCORD_CLIENT_ID`,
  `DISCORD_CLIENT_SECRET` и корректного `WEB_PUBLIC_URL`.
